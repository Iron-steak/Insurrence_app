# Insurrence_app

# Pojišťovna — страховое приложение

Отдельный проект по заданию **Objektové programování a návrhové vzory**. Основное приложение написано на **C# / .NET 9** и полностью работает через консольные меню. Дополнительно сделан **Python GUI (Tkinter)** с клиентской и административной частями. Интерфейс и сообщения приложения — на чешском для защиты проекта.

## Быстрый запуск Python GUI

Из папки `proekt`:

```powershell
python src/python_gui/app.py
```

1. Выберите logger: `file`, `console` или `both`.
2. Нажмите **Spustit C# server**. При первом запуске `dotnet run` соберёт C# приложение.
3. Переключайтесь между вкладками **ZÁKAZNÍK** и **ADMINISTRÁTOR**.

Нужны Python 3.11+ с Tkinter и .NET SDK 9. Python-пакеты устанавливать не нужно. Первое восстановление тестовых NuGet-пакетов требует интернет. Само приложение работает локально.

Если сервер уже запущен, GUI подключится к нему. Выбор logger в GUI действует только для сервера, запускаемого этим GUI. При закрытии GUI останавливает только свой сервер.

## Запуск полностью на C#

```powershell
dotnet run --project src/Insurance.App
```

Появятся два меню: **Administrátor** и **Zákazník**. Есть регистрация клиентов, создание/расчёт страхования, просмотр договоров, продление, отмена, заявления о возмещении, решения и перевод времени. Python для этого режима не требуется.

Для API-режима (например, если хотите запускать сервер отдельно):

```powershell
dotnet run --project src/Insurance.App -- --api
```

Стандартный адрес: `http://127.0.0.1:5090`. UniRent использует другой порт, `5080`, поэтому оба проекта могут работать одновременно.

Консоль и API одного страхового проекта используют одну базу. Запускайте один сервер/консоль на базу: приложение держит эксклюзивный lock-файл. Остановите консоль перед запуском сервера для GUI. Несколько GUI могут подключаться к одному API.

## Что реализовано

### Клиент

- Выбор или регистрация клиента.
- Создание авто- и имущественного страхования на **1–10 лет**.
- Предварительный расчёт цены без сохранения договора.
- Выбор варианта: без франшизы, с франшизой; у авто дополнительно — малый пробег.
- Просмотр своих договоров: будущие, действующие, истёкшие, отменённые.
- Получение предложения продления после подтверждения цены администратором.
- Принятие/отклонение предложения, отмена договора.
- Заявление о страховом событии: дата, описание, сумма ущерба.
- Просмотр расчёта возмещения, решения и выплаченной суммы.
- Перевод времени в месяцах.

### Администратор

- Все договоры всех клиентов и их детали.
- Предложения по заканчивающимся и истёкшим договорам с датой окончания и новой расчётной ценой.
- Подтверждение рассчитанной цены либо ввод другой годовой цены.
- Все заявления о возмещении: подтверждение и выплата расчётной суммы либо отказ с причиной.
- Журнал действий и перевод времени в месяцах.

Выплата означает запись суммы и статуса в учебной модели. Меню ролей предназначены для локальной демонстрации, вход по паролю не реализован.

## Сценарий демонстрации на защите

1. Запустите GUI и сервер, выберите клиента `Jan Novák`.
2. **Nové pojištění:** `Pojištění auta`, `Se spoluúčastí`, предмет `ABC-123`, 1 год, стоимость 300000, возраст 30, пробег 10000, без аварий 5 лет.
3. Нажмите **Spočítat nabídku**: получите **7344 Kč/год**. Создайте договор.
4. **Škodné události:** выберите договор, дату `2026-01-01`, ущерб `40000`, опишите событие. Расчёт возмещения — **35000 Kč**.
5. В **ADMINISTRÁTOR → Žádosti / výplaty** подтвердите заявку. Появятся статус `Vyplaceno`, сумма и запись `ClaimPaid` в аудите.
6. Переведите время на **12 месяцев** из любого меню. Договор станет истёкшим, появится предложение продления.
7. Администратор подтверждает рассчитанную цену или вводит, например, `9000`.
8. Клиент принимает предложение. Создаётся новый договор, связанный с предыдущим, и запись `PolicyRenewed` в журнале.
9. Создайте имущественное страхование с другой стратегией расчёта.
10. Перезапустите приложение: договоры, календарь, предложения, выплаты и аудит сохранятся.

Если база уже содержит данные, используйте актуальную дату в заголовке. Для отдельного чистого сценария можно задать другую папку данных.

## Формулы и правила

Подробные формулы и границы сроков: [docs/RULES.md](docs/RULES.md).

- Авто: стоимость × 4% × коэффициент возраста × коэффициент пробега × бонус без аварий.
- Имущество: стоимость × 0,5% × коэффициент возраста здания × коэффициент охраны.
- С франшизой: страховая премия дешевле на 20%, возмещение уменьшается на `max(5% покрытого ущерба, 5000 Kč)`.
- Малый пробег: до 10000 км/год, скидка 25%, без франшизы.
- Продление: пересчёт риска + тарифный коэффициент `1.03`; администратор может заменить цену.
- Общая сумма возмещений одного договора ограничена страховой стоимостью; ожидающие решения заявления резервируют лимит.

Это явно заданные учебные формулы, а не тарифы реальной страховой компании.

## Настройка логирования через DI

В `src/Insurance.App/appsettings.json` перед запуском:

```json
{
  "Insurance": {
    "Logger": "file",
    "DataDirectory": "data"
  }
}
```

Значения logger:

- `file` — `data/insurance.log`;
- `console` — стандартный вывод;
- `both` — оба места.

При запуске сервера из GUI его стандартный вывод направляется в `data/python-launch.log`, включая `console` logger. В обычном консольном запуске он виден в терминале. GUI также показывает сохранённый аудит независимо от реализации logger.

Альтернатива конфигурационному файлу — переменные окружения:

```powershell
$env:Insurance__Logger = 'both'
$env:Insurance__DataDirectory = 'data-demo'
dotnet run --project src/Insurance.App
```

Папка данных — `data/` в корне проекта (`proekt/data`). Приложение находит её по маркеру `Insurance.sln`, поэтому неважно, откуда запущено (IDE, консоль, GUI); `Insurance:DataDirectory` переопределяет путь. В папке данных находятся `insurance.json`, `insurance.log`, `instance.lock`. Данные сохраняются после каждой операции: сначала временный JSON, затем замена файла. Ошибка операции не меняет состояние; ошибка внешнего logger не отменяет уже сохранённый договор, аудит остаётся в JSON.

Адрес можно изменить через `--urls http://127.0.0.1:5091`. Для подключения GUI к нему задайте `INSURANCE_API_URL` перед запуском Python. Автозапуск из GUI рассчитан на стандартный адрес.

## Откуда взяты архитектурные решения

Проект сознательно опирается на мой первый проект **UniRent** (папка `obj-prog`), часть кода и приёмов оттуда переписана под страховки. Ссылки прямо в комментариях кода:

- фасад `InsuranceService` + хранилище `IStateStore` — как `RentalService` + `RentalDb`/`RentalGate`;
- транзакционный `Update<T>` с клонированием через JSON — развитие защёлки выдачи/возврата в UniRent;
- composition root в `Program.cs` через DI — тот же приём, что в `UniRent.Api`;
- событие `Changed` для наблюдателей — как `RentalEvents`;
- стратегии расчёта в духе `IPricePolicy` (`IInsuranceVariant`), чтобы менять тариф без правки службы;
- HTTP в рабочем потоке через `queue` в Python-GUI — то же, что в GUI UniRent.

## Структура

```text
proekt/
├── Insurance.sln
├── Directory.Build.props
├── data/                        # insurance.json, insurance.log, instance.lock
├── docs/                        # Правила, архитектура и подготовка к защите

    ├── Insurance.Core/
    │   ├── Models.cs                  # Договоры, клиенты, предложения, заявления
    │   ├── Rules.cs                   # Тарифы и лимиты (второй источник: appsettings.json)
    │   ├── Calculations.cs            # Полиморфные продукты, варианты, PricingEngine
    │   ├── InsuranceService.cs        # Все сценарии приложения
    │   └── Storage.cs                 # JSON, logger-интерфейс и реализации
    ├── Insurance.App/
    │   ├── Program.cs                 # DI, конфигурация, HTTP endpoints
    │   ├── ConsoleMenu.cs             # Полноценные C# меню
    │   └── appsettings.json           # Insurance:Rules — тарифы без пересборки
    └── python_gui/
        ├── app.py                     # Tkinter GUI, запросы в отдельном потоке
        └── appearance.py              # Стили, карточки, таблицы
```
